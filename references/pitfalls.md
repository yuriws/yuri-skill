# 踩过的坑 · 尚未验证

历史踩坑清单（写 skill / 开工时的注意事项）＋ 哪些做法已验证、哪些还是空白。

## 踩过的坑

1. **长 Markdown 落盘后必须读回来验证**——曾在大文件生成时串入 5 处英文 / 拼音残片，同一代词连续改错两次。不能凭生成记忆判断。
2. **各章文件的内部小节编号可能不一致**（第 1 章正文是「一、」，第 2/3 章是「二、」）。按固定索引抽取会抽错，要按**节名**定位。
3. **Git Bash 的 heredoc 传含中文的脚本会被错误解码**——需 `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`。
4. **Windows 下 Python 写 `/tmp` 会解析成当前盘符根而失败**——须用 `tempfile.gettempdir()`。
5. **长对话的额度成本是复利式的**——每批（10 章）开新会话清零上下文，让 skill 每次重新读规则库。
6. **笔记里的位置指针要记「章号 + 引文片段」，不要记行号**——归档删单章后行号失效，引文仍可定位（此设计当初是无意的，后来救了场）。
7. **有一类错误机械替换和残留词校验都扫不出来**：语义依赖性别，但字面上**不含任何代词、人名或性别标记**。典型：男主「只剩**一件**内裤」→ 女主应为「内衣和内裤」（件数与品类都要重算；此例由用户发现，AI 自己漏了）。同类高风险：护甲穿着部位、更衣 / 洗澡 / 换装场景、爆装备后「剩几件」的惩罚描写。**唯一防线是通读时逐句问「这句话对女性成立吗」**——grep 校验对这类错误完全无效。（已归纳为**三类**并各自给了改法，见规则 4.9；第四类见 4.35。）
8. **远端操作会偶发失败，不能一次失败就下结论**——实测 `git push` 连败 3 次（代理 502、Empty reply from server）、第 4 次才成功；**查询用的 `ls-remote` 同样会失败**。要重试几次再判定，否则会误判同步状态。
9. **覆盖上传云端文档时，标题不会跟着改**——实测传了 `--title` 也不生效（该参数在覆盖模式下被忽略），必须**再单独调一次重命名接口**。另外产物里不能出现本地路径与内部术语（如正文卷标题里的「真相源，可直接编辑」），上传前要替换成面向读者的标题。
10. **删除任何本地唯一副本前，先校验内容齐全（章节标题齐全 + 字符数合理）＋ 确认远程已有备份**——两步之间必须有校验，不能连着跑。
11. **追加新章前先 grep 关键短语，确认是全新章并定位到真实末尾**——曾在追加时顺手修上一章的过渡句，结果这句被挤到文件末尾造成悬空。
12. **编辑工具基于旧缓存写回会整段覆盖丢失**→ 大文件改用脚本改，改完校验无 HTML 实体（`grep -c '&#x'` 必须为 0）——**实体会让 grep 失效，把按需层变成死库**。
13. **通配匹配要精确**：`glob("vol-*.md")` 会把摘录件 `vol-002-ch021-030.md` 当成正文卷，导致同一批被拼两遍、虚报 40 章（正确 30 章）→ 改用逐字符全匹配。**这是会污染正文的真 bug，不是显示问题。**
14. **否定式过时状态最危险**：「终结技尚未获得」「某角色尚未出场」读着对，实际早已变化，会持续误导后续判断。**查到事实变化就立刻改，不要留着「尚未」二字。**
15. **事实写错比漏改更隐蔽**：设定表写「主角 6 级」实为 5 级（6 级是同伴）——属「同一事实两处写」的又一例。**凡事实，只写一处。**
16. **不要把情节层面的做法钉成硬约束**：曾把一次分装备对话提炼成「以后一律按贡献 + 需求」写进设定表，被判不该钉死。判据：**进设定表前问「这条会改变我后面还没写的章节的写法吗？」** 不会 → 别写进去。
17. **AI 的理由可以是错的，要能被推翻**：曾断言「BOSS 等级原文一般不会出问题」，真因是「记数值的目的（交叉核对）已被取消」，且反例确实存在。**给结论时要给出可检验的判据，别给直觉。**
