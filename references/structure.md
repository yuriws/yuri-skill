# 防 O(n²) 膨胀与工程教训

长篇改写的真正瓶颈不是写正文，是**文档结构**。这一份是硬约束与实测教训。

## 5.0 ⚠️ 最贵的成本不是写正文，是**维持「每轮必读」的上下文**

实测：压缩文档消耗的额度比正文改写还多。根因**不是压缩技巧差，是「每轮必读」清单本身选错了**：

| 误放进每轮必读的东西 | 真实使用频率 | 处置 |
|---|---|---|
| 拉人物出场表、校验清单、批注格式 | **每批一次** | 下沉 DETAIL |
| 设定表的静态块（作品事实 / 术语 / 主角基线 / 结局） | **几乎不变** | 拆静态层 |
| 规则核心层里与正文清单重复的长尾索引 | 已在正文节列出 | 索引只留 DETAIL 专属条目 |

**四条结论，做新项目时直接套**：

1. **区分「规范」与「做法」**。规范＝改文时随手要用（硬护栏、称呼表、人物关系、描写基线、隐性错误清单），必须常驻；做法＝工具使用方法（拉表、校验、写批注、批尾同步），**批级频率，批首读一次就够**。**把做法塞进每轮必读＝为一次批尾动作付每轮的钱。**
2. **「不读」比「读得短」更重要**。静态层拆出去后**每轮开销直接归零**，比任何压缩都有效。
3. **上限改软目标**。硬上限会逼出**无意义的措辞挤压**——为了凑数字改写句子，既伤内容又费 token，还制造「文档必须反复维护」的错觉。**软目标 + 真溢出才整条下沉**。
4. **压缩前先量「固定 vs 可变」**（见 5.1），同样适用于规则库：**先问「这条每轮都要用吗」，再问「怎么压短」。**

## 5.1 滚动摘要（仅「保留单章文件」的项目需要）

若直写卷文件（推荐，见 `init.md`），**不必建滚动摘要**——靠 grep 卷内章标题即可定位。只有保留单章文件、需要一份常驻摘要时，才用下面几条：

- **绝不把摘要抄进第二个文件**：每章文件末尾带累计摘要，是 O(n²) 冗余，长篇数学上不可行。
- **分层**：L0 最近 ≤10 章逐章详情 / L1 每批一条 / L2 压实——**让每轮上下文有天花板**。
- **定上限前先量「固定 vs 可变」占比**，不要按章数拍脑袋。可用窗口 ＝ 上限 − 固定部分；固定区块（头部说明 / 人物状态表 / 待办）常吃掉一半以上预算，导致「每加一章都要压」。
- **人物状态表不进摘要**：与设定表重复，且每多一个角色永久多占几十字。放进设定表，净成本为零。
- **压实按条数触发，不按批触发**：写成「窗口 >10 条就压最老的 5 条」，峰值可控；写成「每批压一次」，批中会出现峰值顶破上限。
- **历史弧线本身也 O(n) 增长**，要单独分层压实，且**配额按实测调整，不预设远期数字**。

## 5.1b 设定表也会膨胀，但**不能蒸馏**

| | 滚动摘要 | 设定表（字典） |
|---|---|---|
| 增长方式 | **累积式**——每章产生新事件，天然 O(n) | 主体**覆盖式**——「等级 3 → 5」是改数字，不是加行 |
| 真正的增量 | 全部 | 只有**角色表**和**术语表** |
| 能否蒸馏 | **能**——丢了细节还有正文卷兜底 | **不能**——概括完就不是字典了 |
| 治理手段 | 分层压实 | **分层归档 + 退出机制**（按需 grep，不每轮读） |

**为什么蒸馏对字典是破坏性的**：「某角色＝女，某种族战士，可靠温柔」一旦被概括成「闺蜜团之一」，下次写到她就完全不知道该怎么改。**设定表的价值就在于可直接查用的确定性。**

**本项目实立的规则**：

- **设定表不设文件级字数上限**：移出「每轮必读」后**只追加、不压缩**，靠下面的**条目级退出机制**治理，两者是不同层级。
- **⚠️ 角色表退出标准＝连续 30 章未再出场 → 移入归档层**。依据：一条剧情线通常 10–30 章，30 章＝一条线加缓冲。（本条与人物速查卡头部一致，**改一处要同步改另一处**——曾出现两边写不同数字）
- **但必须有白名单，否则会误伤**：主角亲属 / 核心同伴团 / **已拍定处置的角色** / 长期对手 **永不退出**。**出场频率 ≠ 重要性**——实测有两名同伴第 10 章时尚未出场、直到第 32 章才登场，但她们的性别与处置是已拍定的决策，绝不能在计数满了之后被移走。判据应写成「**久未出场 且 处置未定案 / 非核心**」，不能只写「久未出场」。
- **归档 ≠ 失忆**：移走时把条目**移入**（不是复制）归档层。改文拉「人物出场表」时**先 grep 活跃层 + 归档层再判断**。**退太早的真正代价不是 grep 成本（很便宜），而是把回来的角色当新角色重新定性 → 产生不一致。**
- **归档条目只留「决策核心」，不留剧情流水**：原名 / 新名 / 性别 / 处置 / 性格标签 / 称呼映射 / 首次出场章号，约 **30–50 字**（比活跃层还短）。剧情流水正文卷里全有。
- **为什么归档层变大不增加开销**（分层的全部意义，容易被误解）：**归档层不进上下文**，只有 grep 命中时才碰，而 grep 只回传**匹配行**而非整个文件。归档层涨到 5 万字，每轮成本仍是 **0**。
- **准入标准**：一次性 NPC 与无名角色**不进设定表**，只记在当批 `notes/batch-NN.md`。
- **动态进度表只留当前活跃线人物**（≤15 行）：已收尾角色的进度行**直接删**——性别与处置留在静态表，历史事件正文卷里有，两边都不丢。

**判断口诀**：**叙事类（摘要）靠压缩，字典类（设定表）靠分层。**

## 5.1c 规则库是第三个膨胀源，且**必须配触发词索引**

盘完所有文档会发现：摘要、设定表都已治理，**只剩规则库没有上限、只增不减**。它和设定表同类（字典 + 流程），所以同样**不能蒸馏、只能分层**：核心层 + 长尾层（按需 grep）。

⚠️ **只把「长尾内容」下沉还不够**：核心层里的「工作方式」节（拉表 / 校验清单 / 批注格式）其实是**做法**，每批只用一次，却常占核心层近三成——这类也要下沉。教训：**分层时要问「这条是规范还是用法」，而不是「这条长不长」**。

**但规则库多了一个设定表没有的陷阱——「不知道自己不知道」。**

设定表的条目是**事后查**的（写到某角色才查他），所以放哪层都行。规则不同：像「衣物件数按性别重算」「含性暴力意象的比喻要换喻体」这类规则，**你不记得它存在，就根本不会想到要查**——分层之后漏掉它们，改写质量会直接下降。

**解法：核心层带一张「触发词索引」表**，覆盖**全部**规则（含长尾），格式是 `触发词 / 场景 | 规则号 | 一句话要点`，约 20 字/条——100 条也才 2000 字。改文时对着扫，命中触发词再去 DETAIL 读全文。**索引是分层不失效的唯一保证。**

**补充规则**：① 隐性错误类规则（grep 扫不出的）**要点必须常驻核心**，不能只留索引；② 新增长尾规则时**必须同步在索引加一行**，否则等于没写；③ 每批收尾的校验清单要覆盖长尾项。

**第四个膨胀源：项目记忆文件的「已定案决策」表**。它每轮注入却只增不减，早晚挤爆。**处置：移到决策记录文件（按需读），记忆文件只留极简索引 + 指针。**

**四条判断规则归总**：

| 内容性质 | 治理手段 | 例子 |
|---|---|---|
| 叙事（事件流水） | **压缩** | 滚动摘要 |
| 字典（可事后查） | **分层归档** | 设定表角色 |
| 流程（须主动想起） | **分层 + 触发词索引** | 规则库 |
| 决策定案 | **移出高频文件，只留索引** | 记忆文件决策表 |

> **实况修正**：记忆文件的决策表**往往并未真正移走**——实测项目里它至今仍保留「已定案决策」节，靠**人工下沉**压回线内。**它是唯一持续贴线的文件。** 原因也真实：**每轮必读的文件最难治理**——不能像设定表那样「移出不读」。所以这一行的正确读法是：**它是优先下沉对象，不是已解决的问题。**

## 5.2 归档（现行做法：改文直写卷文件）

- **改文直接追加进卷文件** `text/vol-00N.md`，**每 100 章一卷**，不建单章；**每章仍单独 git 提交**（单卷约 40 万字；整本一个文件会到 800 万字而不可用）。
- **卷＝真相源，可直接编辑**。位置指针必须记「**章号 + 引文片段**」而不是行号——按章号去卷里搜引文照样能定位。
- **删除任何本地唯一副本前，先确认远程已有备份**——未推送的历史只在本机，丢了就没了。
- **脚本二选一**：`--archive` 追加归档（**按章节标题去重**，重复跑不会写两遍）；无参数生成整合稿，**正文源卷文件优先**（否则单章删光后整合稿就废了）。

## 5.3 工程教训

1. **字数口径统一为「去空白字符数」，禁止裸 `wc -m`**——编辑工具会给 Markdown 补对齐空格，裸字符数虚高数倍（实测某文件 13,588 → 39,520，去空白后仍 13,254）。**误判的代价是真实的内容损失**：曾据此判定两个文件「双双超线」并已动手删冗余，按正确口径重算后发现**四个文件全在线内**。**判断膨胀前必须先确认口径。**
2. **批尾体检必须带「膨胀判断」，不能只记录数字**——只记数字等于没设预警线。做法：实测各常驻文件字数，**逐一对比预警线并标 ✅/⚠️**，越线即整条下沉，不得只记录不处理。**每轮必读的文件最难治理**——它既会自然增长，又不能像设定表那样移出「不读」层。
3. **跨文件重复审计值得每几批跑一次**——实测 26 个 md 去标点后比对（≥10 字）只出 7 条重复，**唯一真缺陷是「硬护栏在三个文件各抄一遍且已不同步」**（一处 4 条、一处只有 3 条）。**低成本、高命中，专门抓「抄列必然不同步」。**
4. **重复处一律改指针，不抄第二遍**——硬护栏、字数口径这类规定，**只在一个文件写全文，别处留一行指针**。教训：规定早已明文存在，又把原理与实例抄进第二份清单，被判「增加重复内容」。**指针不是重复，细节才是。** 唯一例外：若某文件是「每轮只读它、不读权威文件」的，那里**必须**留一行指针（否则会用错口径）。
5. **引用有效性快查**——批尾顺手核一遍常驻文件里引用的路径是否还存在。实测靠这条发现引用了一个已删除的文件。**空洞指针比没有指针更糟**（写了「论证见 DETAIL」但 DETAIL 里根本没有）。
6. **单一真相源**——新事实只进设定表，批注只记「改了什么」，不再两边写。实测速查卡与设定表双写同一批角色，造成 **5 例不同步**。
7. **容器反复超限时，先问「准入是什么」，不是「上限提到哪」**——速查卡字数线连调四次仍触顶；收紧准入（只放「性别 + 称呼」）后一次收干。**上调是治标，收准入是治本。**
8. **会变的数据一律不进常驻层**——等级、装备、技能、数值（血量 / 金价）、字数读数，写下即过时。**例外**：该物品 / 技能本身即剧情约束（不可摘的戒指、必须保密的变身术）。**静态世界观（如城市分区）要记。** 同理，**规则里不要写死会变的读数**（「现 2588，余量 400」改一次烂一次）——只留观察线 + 现测命令。
9. **长篇连载的数值矛盾不修**——前后矛盾是常态，改写者去管**收益接近零而风险不对称**：为修一个数值矛盾而改坏原著（改了装备件数）是赔本买卖。**只管两类**：性转引入的（件数按性别重算）、明显写错会伤及情感线 / 人设的。
10. **不可测的判据 = 不可执行的判据**——「读着吃力就拆」这类主观标准一律换成可数代理（动作计数：凑齐体检步骤 1 次导航＝健康，≥3 次＝散架；字数代理：某两节合计观察线 3,000）。
11. **推送纪律**：代理掉线时先 `curl -x` 探活，**不通就停手、不重试、不裸推**；本地提交可放心积压（实测攒到 30 个），恢复后一次性推完。**远端操作一次失败不能下结论**（历史上 push 连败 3 次、第 4 次才成）。
12. **「定了规则」≠「规则进链」——断链是比「规则不够」更隐蔽的失败**：一条规则若只写进**按需层**（沉淀文档 / DETAIL），而**没进每轮必读的核心层、也没在触发词索引里挂名**，那它**等于不存在**——每轮根本读不到，自然不执行。实测实例：补女性化描写规则拍板后只在沉淀文档落了板，核心层与索引都没有，于是**连续 30 章全部漏执行**（只去男码、漏补女码）；更糟的是**「规则库零新增」的读数把这失败藏住了**。**修法**：规则**同时**写进「每轮核心层（哪怕只留一行指针）＋ 触发词索引」，细则才放按需层。**完成标准**：一条规则「拍板后」的标志是**核心层可见**，不是「文档里写了」。
