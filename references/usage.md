# 换电脑、换会话与按批接续

本说明中的skill路径都相对实际安装目录，项目路径都相对用户当前打开的小说项目。不得照抄原作者电脑的盘符、用户名或代理配置。当前执行记忆版本及验证范围以[execution-memory.md](execution-memory.md)为准；m19尚未证明稳定执行。

## 换电脑准备

完整安装本仓库，保留根目录SKILL.md及references、scripts的相对结构。项目级安装时放在小说项目的`.workbuddy/skills/novel-gender-swap/`；用户级安装按所用工具约定，不硬编码某台机器的用户目录。两处都有同名skill时先确认实际加载位置与版本，避免读到旧副本。

通用skill包含规则、执行记忆和检查方法，不包含某本小说的正文与人物决定。继续已有小说还需取得该书自己的项目文件：项目入口、长期记忆、已定决策、人物与设定表、核心及细则、维护说明、批注和权威正文；改写另需实际原著。只下载skill不能恢复该书进度。项目原著的本地位置和编码在新机器上重新核对。

### 全新电脑：安装当前包

仓库地址：<https://github.com/yuriws/yuri-skill>，分支`main`。做一本新书只需安装此仓库，另备新书原著；不用下载上一部小说项目。执行记忆已包含在`references/execution-memory.md`，不是另一个仓库，也不需要复制旧聊天或逐份收集历史候选。

在新电脑的WorkBuddy中先发送：

```text
请从 https://github.com/yuriws/yuri-skill 的main分支完整安装novel-gender-swap，使用WorkBuddy当前用户的用户级skills目录，文件夹名为novel-gender-swap。
先检查是否已有同名用户级或项目级副本；已有修改先保留并报告差异，不强行覆盖。
保留SKILL.md、references、scripts的相对结构，不要嵌套成novel-gender-swap/yuri-skill/SKILL.md。
安装后实际读取SKILL.md和references/execution-memory.md，回报实际路径、取得的Git提交（能取得时）、规则版本与执行记忆版本，并核对两项澄清：主动增强仅针对已性转女性；未定长期形象按需补问，已定内容实质冲突也须列出处询问。
这一步只安装与核验，不开始改文，也不提交或推送任何小说项目。
```

Windows用户级最终路径应为`%USERPROFILE%\.workbuddy\skills\novel-gender-swap\SKILL.md`。完整目录至少应包括：

```text
novel-gender-swap/
  SKILL.md
  references/
    execution-memory.md
    usage.md
    init.md
    rules.md
    checklist.md
    structure.md
    pitfalls.md
  scripts/
    verify.py
    test_tools.py
    build-merged.py
```

也可用浏览器在GitHub选择Code → Download ZIP，解压后将包含SKILL.md的目录放到上述位置。已经用Git安装的可拉取更新；手动解压的不要把`git pull`当成通用更新方式。

若新电脑已装Git，可在PowerShell执行以下命令，仅用于目标文件夹尚不存在的首次安装：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.workbuddy\skills" | Out-Null
git clone --branch main https://github.com/yuriws/yuri-skill.git "$env:USERPROFILE\.workbuddy\skills\novel-gender-swap"
```

已有Git安装先检查`git status --short`，工作区干净时再`git pull --ff-only`；有本地修改先核对并保留，不使用强制覆盖来更新。`r6`和`m19`标识相同也可能含后续澄清，复现具体安装状态还需记录实际提交。

### 新小说：开独立项目并初始化

在WorkBuddy创建或打开新书专用文件夹，把新书原著放进去，再开该项目的新会话。文件编码由AI实际核对，不能只凭扩展名猜测。给它下面这段启动词，将【原著位置】替换成新电脑上的真实路径：

```text
使用当前已安装的novel-gender-swap，为当前文件夹中的新小说建立改写项目。
原著：【原著位置】。目标是主角男转女、感情线百合化；具体角色处置、形象、改造幅度及感情节奏按本书与我确认。

实际读取SKILL.md、references/execution-memory.md与references/init.md，按需读rules和checklist，回报采用的安装路径、版本及Git提交（能取得时）。新书只沿用通用规则与执行方法，不继承上一部小说的人名、人物关系、年龄、形象、感情进度或章节进度。

先核原著格式、章界与基本人物资料，给出有依据的候选，集中问我开始本书所必需的决定：主角新名、哪些人物性转／保留、主要形象及适用载体、改造幅度、感情处理与各主要人物的节奏、正文保存方式等。尚无信息的人物及长期形象不强行定全。后续实际需要未定长期特征时，先查资料再主动具体补问；已定且一致才不重问，实质冲突须列双方、出处、影响及方案问我。

只记录我已确认的事项，再按init建立决策、设定表与项目规则；有项目记忆机制时只放文件入口指针，不抄一整份规则。项目规则引用本次采用的skill版本，书内设定留在本项目。

本轮先完成开局确认与建库；首批改写在必要决定确认后开始。默认后续10章一批、100章一卷，已有载体要求按我决定。
```

### 决定确认后：首批十章

```text
按已确认的新书决定，连续改写第1—10章，使用本书实际采用的novel-gender-swap与references/execution-memory.md；正文写入已确定的位置。
这次授权连续处理10章，逐章内部检查、批尾集中汇报，不逐章等我确认。确需新决定、未定长期形象或实质设定冲突时具体提问；已有规则足以判断的问题直接处理。

主动增强对象仅为已确定性转女性（含主角）。原著即女性者保留原形象，必要纠错及群像处理另判，不额外补外貌或记浓度欠账。
按主要性转人物分别检查行为成立与具体女性形象。存在缺口时按已定相貌、体态、声线、神态或气质自然改写／补写，不只改代词，不以普通动作冒充形象效果，不设次数及维度配额，不削弱能力。改动与原样保留段都核主体、归因、关系、穿戴与去糙归属。
保存后单独连读正文，再按checklist写批尾，记录本批女性形象与补写的实际效果、候选处理结果、剩余和未检查范围，附实际章号与短引文；机械检查不能替代文学验收。不自动提交或推送。
```

非第1章起步时替换实际章号，并指定必要接续正文。首批完成先看真实改稿，再决定是否继续；不因AI声称“已记住／全部通过”省去抽查。

## 已有小说的新会话启动词

把章号、写入方式及原文位置填好后发送；不要求每轮复制所有细则。

```text
使用当前安装的novel-gender-swap处理我打开的小说项目。
本次处理第【起始】—【结束】章，10章一批；【直接修改权威正文／另存到指定位置】。
原著：【新电脑上的位置及编码】。

实际读取skill的SKILL.md和references/execution-memory.md，报出采用的规则版本、执行记忆版本与安装位置；按入口读取相关规则及checklist，不用旧副本或历史候选代替。
读取本书项目入口、长期记忆、核心规则、人物处置和review-lessons；按需查已定形象、感情方向、细则、维护说明和必要权威前文。既有决定沿用，不重新开局。先核真实章界、权威正文及进度，原著、改稿、实验稿和历史记录分清；本批不全量重读历史报告。

本次授权连续处理这10章，覆盖项目旧的逐章停顿安排；逐章内部检查，批尾集中汇报。确需我决定的新角色或核心设定再暂停，现行规则可判断的问题直接处理。

主动增强仅针对已确定性转女性（含主角），原女性保留原形象，必要纠错另判。女性形象独立检查：不以换名、代词、能力、性格和普通动作替代。有缺口按已定形象自然改写或补写，不设次数和维度配额。同时复核原样保留段的归因、关系、主体和口吻。
保存后单独重读正文，再按主要人物记行为与具体女性形象的分别效果、实际章号及短引文、补写实际效果、候选处理、剩余问题和未检查范围。机械结果不替代语义及文学验收。沿用本书批注和进度入口，不自动提交或推送Git。
```

当前m19仍是待验收试用版，报出版本或读过文件不等于执行通过。候选问题按实际正文处置，不为达到“全部通过”的总结隐瞒剩余。

## 同会话接下一批

“继续第×—×章，沿用本会话指定skill、执行记忆和本书现行决定，10章连续处理；批首更新进度与人物材料，保存后复核，批尾记实际女性形象与补写效果、候选处理、剩余及未查范围。写入范围同上一批，不自动提交或推送。”

上下文已丢失或换会话时重新读入口和执行记忆，不能只凭‘已经记住’续写。

## 换一本小说

使用相同skill和执行记忆，按[init.md](init.md)确认新书角色处置、形象、感情节奏与写入方式。只迁移通用方法，不复制上一本的人名、关系、剧情、慢热安排或项目编号。已有项目沿用其自己的文件布局；上面的文件称谓说明职责，不要求为了套提示词重建目录。
