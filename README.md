# novel-gender-swap

把一部长篇小说做性别转换改写的工作流 skill：主角由男改女，称呼、代词、他人反应全线跟进，感情线改成百合向，情节与结构尽量不动。

它把改写过程沉淀成三份基础文件（决策记录、设定表、规则库），按「每 10 章一批」推进，批末做一致性体检。换会话、隔几天再回来，读文件就能接着改，不靠记忆。

这是在可复用工作流上按用户明确偏好定制的个人版skill，适用于都市、历史、武侠、仙侠、科幻、游戏等题材。规则先写目标与判断方法，案例注明前提；关键词、相邻窗口及列举场景只帮助定位，不作为启动检查的门槛。先按目标检查，再决定保留或修改，真实设定及内容边界仍遵守。项目设定和感情方向仍按书确认。

适用于支持 skill 机制的 AI 工具。只提供方法论与流程，不含任何小说原文；改他人作品仅供自用，公开发布需自行取得授权。

## 换电脑与执行记忆

本仓库自带[执行记忆](references/execution-memory.md)和[跨设备使用说明与启动词](references/usage.md)，无需读取原作者电脑上的文件。当前m12在m11基础上补充返修后核对实际正文与项目记录的方法，最新实验尚未独立验收，不能视为已稳定或跨项目通过。

**全新电脑开新书**：按[从安装到首批十章的操作说明](references/usage.md#全新电脑安装当前包)，依次完成完整安装、独立项目开局确认、首批改写。执行记忆只有`references/execution-memory.md`这一个当前入口，已包含在本仓库；新书不需要下载上一部小说项目。

在另一台电脑完整安装仓库；继续已有小说，还要单独同步该书的项目规则、设定、长期记忆、批注、权威正文及实际原著。新会话实际读取skill入口、执行记忆及该书项目入口，不靠会话口头记忆。项目专用内容留在小说项目，不混入通用skill。

## 首次使用与已确认偏好

准备原文文件（UTF-8的txt最稳）。开局确认主角新名、改造幅度、角色处置、主要形象体格、感情处理与结局，不要求一次定全。后续实际需要尚未确定的长期形象时，先查设定与可靠前文再主动补问；已定且一致者不重复问，实质冲突须列双方、出处、影响及方案询问后再定。

这个个人版已确认三项长期偏好：主角和已性转角色的粗口必须修改；西装等强男性编码正式服装换为女士套装、礼服等且保功能；女性外貌不用“英俊、硬朗、棱角分明”等词。它们是个人风格要求，不是对所有女性的普遍判断。

女性形象塑造是独立目标：分别验收主要性转角色的性格／能力／行为，以及连续阅读中的具体女性形象，前者不代替后者。先找整场及必要前文的形象缺口，再选已有动作、对话、观察或过渡展开；已有动作也能补写，抽象句不逐个补。可正面呈现已定相貌、整体身形、声线、神态与气质，不强制微动作、旁人评价或恋爱视角。符合人物、场景与视角的瞬时细节可自然补写，保事实与因果（4.41①）；不设次数／维度配额，不削弱能力。批尾按主要人物分别记录性格与女性形象效果、正文证据及未完成范围，不逐段计数，不用普通动作单独证明补足。身体词按语境判，不物化、不露骨、不用尺寸或部位扫描堆砌；自然欣赏与吸引不因同为女性而删除。

主动增强仅针对已确定性转女性（包括主角）。原著即女性的人物保留原有形象，不因戏份多就额外补外貌或列浓度欠账；必要的指代、关系、事实、群像与衔接修订另按对应规则处理。

主要感情线按书、按人物在开局确认后沿用。可以慢热、先自知、双向暗恋、直球或其他方式；自知、双方确认和对外公开分别判断。删除不成立的配对机制后，有信息缺口才补，不强制等量铺垫，也不预设百合一定更慢或需要更多铺垫。

## 工作流

先建`feasibility.md`决策、`GLOSSARY.md`设定表、`RULES.md`项目规则。默认每10章一批：读规则与相关人物设定 → 定位章界和在场人物 → 逐章精修 → 分类列改动 → 批末校验 → 归档同步 → 批尾体检。定位、查证、校验和汇报按批合并，新的核心决策不能合并跳过。

| 类别 | 内容 |
|---|---|
| A | 已定人名、称呼和正确指代的机械替换 |
| B | 修复性转后的因果、视角、关系、群像分配，及按已定女性形象所需的改写／补写；去糙单列 |
| C | 原文没有、另加的关系／性别互动张力；单列确认，每章≤3处是上限，不是目标 |
| D | 与性转无关的校对，标可回退 |
| E | 首次确立已定性别／形象，写进设定表 |

所有题材首次提及时明确已定性别，真正登场建立具体女性形象；主动复核原性别牵动的穿戴、数量、动作、身份关系及生活安排。去糙按表达归属，主角及性转人物的内心不因无引号归旁白，改后复查替换词，旧批记录不豁免；其他人物／叙述者另判。代词逐处核所指，同句可指不同人物，改后连读消歧。角色归档保留完整的后续相关设定。

C上限不限制全部新增句，也不是女性描写配额。修复因果归B、首次确立归E，不给新增恋爱推进换标签绕过C。

默认Markdown流程直接写`text/vol-00N.md`、每100章一卷，整合稿为生成物；既有项目沿用已定正文载体，明确权威来源并核完整性，不为套脚本自动转换Word等文档。归档与清理分开，覆盖／清理前确认可恢复备份；提交按项目约定，推送／上传／发布分别依用户授权。每10章建`notes/batch-NN.md`。常驻内容按需要分层，不为凑字数反复压缩。

换会话时读入口、项目核心规则、相关角色处置与形象／关系、进度指针和当批原文；需要时检索前文，不无条件重读全部历史。规则版本取自[SKILL.md](SKILL.md)，项目记录实际采用版本。新语义规则须评估旧稿影响并登记已处理／待处理范围；更新skill不意味着旧项目和旧稿自动同步。

在skill目录运行：

```text
python scripts/verify.py
python scripts/test_tools.py -v
```

`verify.py`不核验小说正文、文学效果、远程链接内容或Markdown片段锚点；已知专名零命中也不能证明没有未知专名。语义与文学效果须另外通读和用认可的改稿校准。

把`build-merged.py`拷到**小说项目根目录**后运行：

```text
python build-merged.py
python build-merged.py --archive
```

无参数仅接受纯卷或纯数字单章一种来源，混合时明确报错；摘录文件不参与。仅处理标题`## 第NN章《标题》`；实际章序必须连续、唯一、升序且归卷正确，可从非第1章开始处理连续摘段。不会发现来源之外缺失的首尾章节。

归档先验证整批，再写入；同章同标题正文跳过，同号改标题或正文报冲突，不把中间回填章节追加到末尾。单章输入不自动删除。归档后仍混合时，应先核验卷完整、确认可恢复备份，再自行清理或移走已归档单章，之后生成整合稿。每个目标文件使用原子替换；多卷写入不构成跨文件事务，磁盘错误时需核对已写文件再重试。

## 边界

不凭空改剧情、世界观、能力或人物内核；原有女性角色保人物内核、能力与必要功能；失效的称呼、关系、因果及群像分配按需修复（4.35b）。女性形象是否充分另按4.41独立判断，可自然补写。未成年角色与露骨内容等硬护栏见[规则4.10](references/rules.md#410-硬护栏不可协商)。改写他人作品公开发布须确认授权，skill本身不包含小说原文。
