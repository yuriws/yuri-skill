# novel-gender-swap

把一部长篇小说做性别转换改写的工作流 skill：主角由男改女，称呼、代词、他人反应全线跟进，感情线改成百合向，情节与结构尽量不动。

它把改写过程沉淀成三份基础文件（决策记录、设定表、规则库），按「每 10 章一批」推进，批末做一致性体检。换会话、隔几天再回来，读文件就能接着改，不靠记忆。

这是在可复用工作流上按用户明确偏好定制的个人版skill；项目设定和感情方向仍按书确认。

适用于支持 skill 机制的 AI 工具。只提供方法论与流程，不含任何小说原文；改他人作品仅供自用，公开发布需自行取得授权。

## 首次使用与已确认偏好

准备原文文件（UTF-8的txt最稳）。开局确认主角新名、改造幅度、角色处置、形象体格、感情处理与结局；信息不足的角色出场时再定。已确认的事项登记后不反复询问。

这个个人版已确认三项长期偏好：主角和已性转角色的粗口必须修改；西装等强男性编码正式服装换为女士套装、礼服等且保功能；女性外貌不用“英俊、硬朗、棱角分明”等词。它们是个人风格要求，不是对所有女性的普遍判断。

女性形象允许外貌、身形、气质、声音、语气、动作、内心与关系互动，允许直接形容和通用词；不靠凑次数、固定词表或削弱能力体现。身体词按语境判，不物化、不露骨，不用尺寸或部位扫描堆砌。自然欣赏与吸引不因同为女性而删除。

主要感情线按书、按人物在开局确认后沿用。可以慢热、先自知、双向暗恋、直球或其他方式；自知、双方确认和对外公开分别判断。删除不成立的配对机制后，有信息缺口才补，不强制等量铺垫，也不预设百合一定更慢或需要更多铺垫。

## 工作流

先建`feasibility.md`决策、`GLOSSARY.md`设定表、`RULES.md`项目规则。默认每10章一批：读规则与相关人物设定 → 定位章界和在场人物 → 逐章精修 → 分类列改动 → 批末校验 → 归档同步 → 批尾体检。定位、查证、校验和汇报按批合并，新的核心决策不能合并跳过。

| 类别 | 内容 |
|---|---|
| A | 已定人名、称呼和正确指代的机械替换 |
| B | 修复性转后的因果、视角、关系与必要形象表达；去糙单列 |
| C | 原文没有、另加的关系／性别互动张力；单列确认，每章≤3处是上限，不是目标 |
| D | 与性转无关的校对，标可回退 |
| E | 首次确立已定性别／形象，写进设定表 |

C上限不限制全部新增句，也不是女性描写配额。修复因果归B、首次确立归E，不给新增恋爱推进换标签绕过C。

正文直接写进`text/vol-00N.md`，每100章一卷，不建立第二份可编辑整合稿。每10章建`notes/batch-NN.md`。常驻内容按需要分层，不为凑字数反复压缩。

换会话时读入口、项目核心规则、相关角色处置与形象／关系、进度指针和当批原文；需要时检索前文，不无条件重读全部历史。规则版本取自[SKILL.md](SKILL.md)，项目记录实际采用版本。新语义规则须评估旧稿影响并登记已处理／待处理范围；更新skill不意味着旧项目和旧稿自动同步。

## 配套文件与脚本

| 文件 | 用途 |
|---|---|
| [SKILL.md](SKILL.md) | 原则、个人偏好、开局、工作流、分类、规则可见入口 |
| [references/rules.md](references/rules.md) | 判断细则与情境示例 |
| [references/checklist.md](references/checklist.md) | 机械、候选和语义分层复核，批尾模板的唯一出处 |
| [references/init.md](references/init.md) | 项目骨架、确认与登记、脚本约定 |
| [references/structure.md](references/structure.md) | 分层、版本、存量与文档维护 |
| [references/pitfalls.md](references/pitfalls.md) | 历史经验、适用范围与验证限制 |
| [scripts/verify.py](scripts/verify.py) | skill机械检查：已知专名、规则ID集合及重复、护栏文字、唯一模板、本地Markdown文件链接、脚本语法 |
| [scripts/build-merged.py](scripts/build-merged.py) | 卷／旧单章整合及追加归档，校验章号、顺序、区间与冲突 |
| [scripts/test_tools.py](scripts/test_tools.py) | 标准库回归测试，均使用临时样本，不读取或修改真实小说 |

在skill目录运行：

```text
python scripts/verify.py
python scripts/test_tools.py -v
```

`verify.py`不核验小说正文、文学效果、远程链接内容或Markdown片段锚点；已知专名零命中也不能证明没有未知专名。语义与文学效果须另外通读和用认可的改稿校准。

把`build-merged.py`拷到**小说项目根目录**后运行：

```text
python build-merged.py
python build-merged.py --archive
```

无参数仅接受纯卷或纯数字单章一种来源，混合时明确报错；摘录文件不参与。仅处理标题`## 第NN章《标题》`；实际章序必须连续、唯一、升序且归卷正确，可从非第1章开始处理连续摘段。不会发现来源之外缺失的首尾章节。

归档先验证整批，再写入；同章同标题正文跳过，同号改标题或正文报冲突，不把中间回填章节追加到末尾。单章输入不自动删除。归档后仍混合时，应先核验卷完整、确认可恢复备份，再自行清理或移走已归档单章，之后生成整合稿。每个目标文件使用原子替换；多卷写入不构成跨文件事务，磁盘错误时需核对已写文件再重试。

## 边界

不凭空改剧情、世界观、能力或人物内核；原有女性角色通常保留，涉及性转后失效的关系、称呼与因果时做必要修复。未成年角色与露骨内容等硬护栏见[规则4.10](references/rules.md#410-硬护栏不可协商)。改写他人作品公开发布须确认授权，skill本身不包含小说原文。
